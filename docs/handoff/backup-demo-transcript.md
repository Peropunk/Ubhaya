# Five-minute backup walkthrough

This narrated walkthrough uses captures from the running synthetic demo.
The local voice is synthesized. The original browser interaction recording
is available separately.

## 00:00 · Case overview

This is Ubhaya, an offline prototype for reviewing the fictional P C fourteen
case. We start at the evidence intake screen. There are twelve artifacts,
three statements, and two hundred and seventy-six parsed events. The
artifact list shows the source and a fingerprint for each original file.
Clicking Verify all hashes recalculates those fingerprints. The case header
also displays the audit chain status.

## 00:35 · Statements

The case contains statements in English, Hinglish and Hindi. Analyze case
loads the bundled exact-quote annotations and runs the deterministic
matcher. The colored claims are interactive. Each one opens its verdict
and supporting records. The cached benchmark matched all eighteen expected
quote spans and verdicts. The local model comparison remains open because
the tested models missed the thirty-second latency target.

## 01:10 · Claim detail

Follow the manager's statement that files were copied around twenty-two
fifteen. The system finds supporting USB and copy records within the time
window. The detail shows the claimed words, the verdict, the evidence
strength, and direct links to the source. The account board keeps the
question of who operated the machine open. An account event establishes
account activity and the source records carry their own limits.

## 01:50 · Original evidence

Open row twenty-two from the PC event log. The highlighted source shows
sixteen forty-four and five seconds in coordinated universal time. The
normalized time is twenty-two fourteen and five seconds in Indian
standard time. The time engine allows one minute of uncertainty on either
side. The original timestamp, source timezone, row number and stored source
bytes are preserved.

## 02:25 · Clock calibration

The camera timeline shows the entrance and corridor readings. Disable
clock calibration to surface the possible ordering conflict. The corridor
camera appears to place its sighting before the entrance camera. With the
documented seven-minute adjustment and its uncertainty applied, the
corridor event moves to twenty-two twelve and forty seconds, with one
minute on either side. The possible conflict clears.

## 03:07 · Human review

The visitor badge appears twice, forty-two seconds apart. A reviewer can
reject the alert as a possible double tap and record the reason. This
preserves the source and the review decision. The blurry corridor frame
remains listed for manual entry. The reviewer can open the frame, confirm
a source time where possible, and preserve that entry in the audit trail.

## 03:47 · Next evidence

The next evidence screen shows the suggested visitor-card register,
entrance video from the dhaba, and relevant telecom records. The score
shows dispute impact, feasibility, privacy cost, and urgency. The
drafts refer to specific claims. The telecom draft leaves the subscriber
identifier for verification. The reviewer can inspect the drafts and
export the case as JSON or a printable PDF.

## 04:27 · Results and limitations

The account board groups supported, contradicted and open claims for each
speaker. The synthetic evaluation found all five planted contradictions.
The double-tap alert is tracked separately and the reviewed export shows
the analyst's decision. The repeatable cached workflow can run with only
the local server available. The next project gate is live extraction
qualification and a run on the laptop selected for the presentation.
